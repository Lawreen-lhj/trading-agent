# A股短线简报（交易 Agent · P0）

**每个交易日盘前跑一次，产出「短线交易计划」+ 一条 macOS 本地通知。**
不接下单、不接实盘、不调 LLM。用户风格已定为**短线（持股 2-5 日）**，
评分模型、提醒规则、输出形态都围绕这个目标设计。

## 它做什么

- **市场层**：指数、涨跌家数、成交额、涨停/跌停家数 → **短线市场温度**（赚钱效应 0-100）
  ——指数涨不涨和短线能不能做经常是两件事，温度比指数重要
- **外围层**（只看不做）：美股三大指数、恒指 / 恒生科技、BTC / ETH
- **自选池评分（短线版）**：动量28 + 量价24 + 形态22 + 结构16 + 空间10 − **过热罚分**
  - 动量主因子是 RET5/RET10（不是 RET20），且用"甜点区"曲线：涨 3%~12% 最优，涨超 20% 反而降分
  - **过热是负分项**：BIAS5 偏离、RSI6、连涨天数、贴布林上轨都会扣分——短线最贵的错误是追高
- **交易计划（核心输出）**：每只票推导 买点区间 / 止损 / 两档目标 / 盈亏比 / 建议股数
  - 止损 = min(MA10−0.4×ATR, 收盘−1.5×ATR)，宽度限制在 1.5%~6%
  - 目标① 不超过上方前高（创新高则无阻力限制）
  - 盈亏比 < min_rr 或评分 < min_score → 不给计划，并写明原因
  - 股数按「单笔风险 1% 总资金」反推，单票上限 30% 仓位
- **卖出信号**：跌破 MA10（放量/缩量分级）、放量滞涨、冲高回落、RSI6 过热、偏离过大、连涨过多、**时间止损**（超 max_hold_days 直接 P0）
- **持仓**：止损距离、持有天数、成本-7% 兜底止损；止损被击穿显式标「已破止损」
- **留痕**：评分、信号、**每天的完整交易计划**全部落 SQLite——
  短线唯一能验证"这套规则有没有用"的办法，就是事后核对买点能不能成交、止损有没有被打掉

## 用法

**推荐：本地 Web 控制台**（界面改配置、一键运行、看提醒和历史）

```bash
cd trading-agent
.venv/bin/python server.py        # 打开 http://127.0.0.1:8765，自动弹出浏览器
```

控制台只有本机能访问（只监听 127.0.0.1），包含：

- **仪表盘**：市场温度、指数与外围、可执行计划、P0/P1 提醒、数据缺口
- **交易计划**：今日全部计划（含「不满足」的原因）、历史计划留痕、出手频率统计
- **自选池 / 持仓**：增删改直接写回 `config.yaml`（保存前逐字段校验，旧文件自动备份到 `data/backup/`）
- **提醒**：历史告警检索，按级别 / 日期过滤，用于校验规则有没有误报
- **简报历史**：每天的 HTML 存档内嵌预览
- **设置**：交易风格、风控参数、提醒阈值、通知开关（可发测试通知）
- **运行简报**：右下角实时日志浮层；同一时刻只允许一次运行（并发打接口会被限流）

命令行照旧可用：

```bash
.venv/bin/python run_brief.py              # 完整跑一遍（含本地通知）
.venv/bin/python run_brief.py --no-notify  # 只出报告不弹通知
```

首次在新机器上装环境：

```bash
python3 -m venv .venv
.venv/bin/pip install pyyaml -i https://pypi.tuna.tsinghua.edu.cn/simple
```

> 国内网络始终用清华镜像，官方 PyPI 走代理只有 ~20KB/s。

输出在 `data/briefings/YYYY-MM-DD.html`（给人看）和 `.json`（给 agent 读），
评分、信号、每天的完整交易计划落 `data/market.db`。

## 改什么

全部在 `config.yaml`：

- `watchlist`（**当前是示例池，务必替换**；短线建议 10-20 只）
- `holdings`（短线强烈建议填，带 `opened` 日期才有时间止损）
- `risk`：`capital` 总资金、`single_risk_pct` 单笔风险、`max_hold_days`、`min_rr`、`min_score`
- `thresholds`：短线提醒阈值
- `meta.style`：`short`（短线）/ `swing`（波段，走 `scoring.py` 老模型）

## 架构

```
server.py              本地 Web 控制台（标准库 http.server，只监听 127.0.0.1）
run_brief.py            入口：采集 → 指标 → 评分/计划 → 信号 → 渲染 → 通知 → 落库
web/                    控制台前端（原生 HTML/CSS/JS，无框架无 CDN）
src/
  configstore.py        配置读写：逐字段校验 + 备份 + 原子写入，UI 的唯一写入口
  datasource.py         统一数据层：主源东财 → 备源腾讯；日线+市场级数据双缓存
  em.py                 东方财富 push2 接口（ut token、多镜像主机轮换）
  tx.py                 腾讯行情（GBK 文本协议），仅作备源
  net.py                全局限速 350ms + 重试 + 指数退避
  indicators.py         技术指标（含短线：RSI6/KDJ/BOLL/BIAS/ATR%/close_pos/连涨天数）
  shortterm.py          短线评分 + 交易计划 + 短线信号 + 市场温度
  scoring.py            波段评分（style=swing 时用）/ 市场状态
  briefing.py           HTML 渲染（纯 CSS + 内联 SVG，零 JS 零 CDN）
  notify.py             macOS 通知（osascript）
  db.py                 SQLite 留痕（runs / watch_rows / alerts / plans）
```

**依赖只有 pyyaml 一个**。数据直连东方财富公开接口（akshare 底下那层）。

## 设计上的几个硬决定（都是踩坑换来的）

**1. 数据源必须双轨 + 市场级缓存。**
东财会随机限流（连接直接被掐断，本机已被封过多次）。行情走腾讯备源；
只有东才有的涨跌家数/行业板块，失败时回落到**当日缓存**并标注时点（`stale_asof`），
不当实时数据用但也不整段缺失。所有来源在页脚写明。

**2. 指标用代码算，不用 LLM 算。**
模型只解释"为什么"，不算"是多少"。计划里的每一个价格都是确定性推导，可复现。

**3. 评分与计划必须一致。**
第一版出现过「评分 32 分（回避）却 ready=True 给出买入计划」的自相矛盾，
已加一致性校验：评分不过观察线就不给计划。

**4. 创新高不能拿自己的高点当阻力。**
第一版茅台刚创 20 日新高，盈亏比算出 0.2——因为把"今天的高点"当成了上方阻力。
已改为：收盘在前高下方才算阻力，创新高时用 60 日高或纯 ATR 目标。

**5. 止损必须宽于噪音。**
第一版止损取"更紧"的一个，招行算出 1.85% 止损（不足 1 ATR），
日内正常波动就会打掉。已改为取**更宽**的（MA10−0.4ATR 与 1.5ATR），
宽度上限 6%——代价是仓位变小，这是应该付出的代价。

**6. 「回踩」必须有趋势前提。**
均线空头排列时价格贴着 MA5，那是暴跌后的弱反弹，不是低吸窗口。
回踩信号要求 MA5 > MA10 且收盘守住 MA10。

**7. 不用 JS 图表；缺数据就说缺，不硬凑。**
同前版，不变。

## 已知限制

- 东财被限流时市场温度、行业板块会用缓存或缺失（页脚注明）
- 节假日不判断交易日历；时间止损按自然工作日粗算，不含节假日
- 腾讯备源不提供换手率，走备源当天「换手相对强度」退化为绝对换手口径
- 当前只有盘前一次；**盘中异动监控（短线刚需）在 P3**

## 下一步

- **P1**：全市场筛选扩池（短线池不该只有 10 只票可选）
- **P2**：模拟撮合按计划自动记账（T+1、涨跌停、100 股整数），收盘自动核对当日计划成交情况
- **P3**：盘中异动监控（9:40-15:00 每 5 分钟，纯代码阈值，命中才通知）
- 盘后复盘简报（15:10）：当日计划 vs 实际走势逐条核对

## 版本管理

已初始化 git 仓库（分支 `main`）。**只有代码和配置入库**，运行时数据不进 git：

```bash
git log --oneline          # 看改动历史
git status                 # 看当前变更
git add -A && git commit -m "说明"
```

被 `.gitignore` 排除的内容：`.venv/`、`data/market.db`（每日计划留痕）、
`data/briefings/`（每日简报）、`data/cache/`（日线缓存）、`data/backup/`（配置备份）、开发截图。

理由：这些每天都会变，二进制或大段 diff 没有版本价值；真正要版本化的是**规则**本身——
评分逻辑、风控参数、提醒阈值。想连简报一起归档，把 `.gitignore` 里 `data/briefings/` 那行删掉即可。

尚未配置远程仓库。要加的时候：

```bash
git remote add origin <仓库地址>
git push -u origin main
```

> `config.yaml` 含你的自选股与资金设置，**远程仓库请务必用私有**。
